# 余光 / Glance：项目计划

本文档讲如何把余光从一个个人项目一步步做到盈利。它以[《方向与原则》](01-direction-and-principles.md)为边界。

- **不排时间表，只排优先级。** 前一步的"过关标准"没达到，就不进入下一步。
- **每个决策都写明理由。** 理由不成立了，决策就该改。
- 文中的价格、成本、指标都是**待验证的假设**，以实际访谈和测试结果为准。

---

## 总览：优先级顺序

| 优先级 | 事项 | 一句话目的 |
|---|---|---|
| P1 | 选定切入领域：HDB/BTO 收房验房 | 选一个"重要"有标准、漏检有代价、能快速接触客户的领域 |
| P2 | 收集数据（不买硬件） | 用公开视频和自拍素材起步 |
| P3 | 建立评测集和标注规范 | 先定义"答对"，才能衡量召回率 |
| P4 | 离线 MVP pipeline | 视频和目标清单进，逐项状态和证据出 |
| P5 | 测试与基准 | 用数字证明"比人多找出漏项" |
| P6 | 需求访谈 | 确认痛点、预算和决策者 |
| P7 | 免费分析与人工兜底交付 | 在真实客户数据上验证价值 |
| P8 | 付费试点 | 拿到第一笔钱，验证定价 |
| P9 | 证据层 v1 | 让报告可以被第三方复核 |
| P10 | 产品化 | 让客户无需我们介入也能用 |
| P11 | 实时化：手机 → 眼镜和边缘设备 | 客户要求现场提醒时再做 |
| P12 | 第二个垂直领域或第二个市场 | 复用 pipeline，扩大收入 |
| P13 | 盈利与退出准备 | 主业化；为被收购做准备 |

P1–P5 和 P6 可以并行：一边做 demo，一边约访谈。demo 本身就是访谈时最好的信用背书。

---

## P1. 切入领域：HDB/BTO 收房验房

### 决策
新加坡的 HDB/BTO（以及 EC 和公寓）收房验房：验房公司或业主在收房时逐项检查新房缺陷，出具报告，再向建屋局（HDB）或开发商申请维修。

### 理由
1. **"重要"有现成的标准。** 验房本来就有 100 多项检查清单（墙面、地面、天花板、门窗、水电、五金等），"重要"不需要我们定义，召回率可以直接量化。
2. **漏检的代价明确。** 缺陷保修期一般是收房后一年，而且实际上缺陷要在装修开始前报，过了时间窗口就只能业主自己出钱。漏一项，就是业主的真金白银。
3. **天然是第一人称形态。** 验房师拿着手机、手电和工具在空房里走，固定摄像头做不了这件事。
4. **有现成的人工报告可以对比。** 每次验房都有一份带照片的报告。拿系统结果和它对比，就能算出我们比人多找出了什么，这是最直观的价值证明。
5. **"证"有天然需求。** 报告本身就是向建屋局或开发商索赔的证据，可复核的证据链能直接提高索赔成功率。
6. **客户分散、决策链短。** 验房公司多是小公司，能直接找到老板，销售周期以周计，而不是以年计。
7. **能当客户。** 创始人可以自己花钱请一次验房，或者陪朋友收房，获得完整的一手体验。
8. **公开数据多。** YouTube、TikTok、Lemon8 上有大量收房验房视频，不买硬件也能开始。
9. **隐私风险低。** 空房、没有旁人，录像合规成本远低于有人出入的场景。
10. **可以复制。** 同一套能力可以迁移到公寓交房、商业物业交付、物业巡检，以及中国、澳洲的验房市场。

### 已知缺点（坦白记录）
- **单价低。** 一次验房几百新币以内，客户单价小，新加坡的市场总量有限。**这就是为什么它是切入点而不是终点。**我们要的是快速验证和第一批收入，而不是规模。
- 收房量跟着 BTO 交付批次走，需求有季节性。

### 考虑过但没有作为首选的方向

| 方向 | 不先做的原因 |
|---|---|
| 安保巡逻 | 客户是大型安保公司和政府合同，决策慢；适合作为"证"的第二个领域 |
| 线下销售对话分析 | 赛道拥挤；容易变成监控员工，违背原则 |
| 工业和电力巡检 | 销售周期长、需要资质，实时安全告警的认证门槛高 |
| 旅游、生活类 C 端 | 没有付费方，"重要"无法统一定义；只用作概念演示素材 |

## P2. 收集数据（不买硬件）

### 决策
数据分三类，各有用途：

| 类别 | 来源 | 用途 |
|---|---|---|
| **评测集** | 公开的新加坡收房验房视频（优先选验房师边看边讲解的）；后期加入客户授权的录像 | 计算召回率 |
| **概念演示** | 看房 vlog、街头漫步、旅游视频；自己用手机拍的素材 | 对外讲故事，不用于计算指标 |

### 理由
- **不买硬件**：现阶段要验证的是"能不能找出漏项"和"有没有人付钱"，跟用什么设备采集无关。手机和公开视频已经足够。
- **优先选有讲解的视频**：讲解内容就等于"验房师注意到了什么"的标注，可以直接当作人工基线来对比。
- **概念演示和评测分开**：旅游视频没有统一的"重要"标准，混进评测集会让指标失去意义。
- **版权**：公开视频只用于内部研发，不公开发布处理后的版本；对外 demo 用自拍素材或经授权的视频。发视频的验房公司**本身就是潜在客户**，请他们授权正好可以作为第一次接触。

## P3. 评测集和标注规范

### 决策
在写 pipeline 之前，先建一个小评测集：**10 段验房视频**，按统一的标注规范，逐条标出所有缺陷（类别、位置、时间戳、严重程度）。

### 理由
- 召回率是核心价值。没有"标准答案"，就无法知道改动是变好还是变坏。
- 先标注能逼自己吃透验房这件事，标注的过程本身就是在学习这个领域。
- 小而精，胜过大而糙。10 段高质量标注足以发现系统性问题。

### 标注规范要点
- 缺陷类别直接采用验房清单的分类，与行业对齐。
- 每条缺陷记录：类别、房间、时间戳、最佳证据帧、严重程度、视频里的验房师有没有提到。
- 最后一项"有没有提到"就是**人工基线**：人注意到了多少。
- 条件允许时，请一位资深验房师复核标注，并把他补充的条目单独记录下来。

## P4. 离线 MVP pipeline

### 决策
```
视频文件 + 目标清单
 → 抽帧（场景变化检测 + 固定间隔兜底）
 → 语音转写（带时间戳）
 → 视觉大模型按清单逐项查找（局部切块放大）
 → 跨帧合并同一缺陷，挑出最佳证据帧
 → 清单逐项给出状态：发现问题 / 已检查无问题 / 镜头未覆盖
 → 输出报告：每项的状态、位置、时间戳、截图、置信度、判断依据
```

### 选型与理由

| 选型 | 理由 |
|---|---|
| **离线处理视频文件** | 成本最低、迭代最快；验房本来就是"先验完再出报告"，离线完全够用 |
| **调用模型 API，不自己部署** | 早期迭代速度第一；模型可以随时换成更强或更便宜的 |
| **模型调用抽象成接口** | 遵守"模型无关"原则；同一个评测集可以横向对比不同模型 |
| **目标驱动：带着清单去看，不判断人看了什么** | 人眼看到不等于注意到，推断人的注意力既难又不可靠。AI 带着明确的目标逐项去盯，替人分担"记着目标"的脑力，这才是核心价值 |
| **逐项给出三种状态，包括"镜头未覆盖"** | 没被检查到的项目是最危险的遗漏，连模型都看不到。明确指出来，人才知道要补拍或补查 |
| **和人工报告的对比只用来衡量价值** | 对比结果用于测试和销售时证明"多找出了什么"，不是产品判断的依据 |
| **按清单逐项查找，而不是让模型自由描述** | 自由描述会漏掉不显眼的小缺陷；逐项主动查找是提高召回率的关键 |
| **局部切块放大** | 裂缝、划痕、缝隙都很小，整张图上模型看不出来 |
| **先多召回，再用校验步骤过滤误报** | 召回优先；误报可以由人工兜底筛掉，漏报却找不回来 |
| **声画融合** | 验房师说"这块砖空鼓"，把这句话和画面对上，既能当人工基线，也能补充视觉信息 |
| **报告格式贴近行业报告** | 客户能直接拿去用，降低接受门槛 |
| **命令行工具起步，不做界面** | 早期只有自己用，界面是 P10 的事 |

## P5. 测试与基准

### 指标

| 指标 | 含义 | 为什么重要 |
|---|---|---|
| **召回率**（在精确率不低于设定门槛的前提下） | 标准答案里被找到了多少 | 核心价值 |
| **额外找回数** | 验房师没提到、但系统找到并经确认的缺陷数 | 对客户最有说服力的数字 |
| 分类别召回率 | 每类缺陷各自的召回率 | 找出短板，指导优化方向 |
| 覆盖度准确率 | 系统判断"镜头未覆盖"的项目，是否真的没被拍到 | 指出没检查到的项目，是余光独有的价值 |
| 每小时视频误报数 | 人工复核的负担 | 决定人工兜底的成本 |
| 每小时视频成本 | 模型调用和计算费用 | 决定定价下限 |

### 测试方法
- **留出测试集**：评测集分成开发集和测试集，测试集不参与调 prompt，防止"背答案"。
- **回归测试**：每次换模型、改 prompt、改流程，都完整跑一遍评测，结果存档对比。
- **盲评**：条件允许时，由不知道哪些条目是系统找到的人来判断条目是否成立。

### 过关标准（进入 P7 的前提）
- 系统在测试集上的召回率**明显高于**视频里验房师的口述覆盖率；
- 每段视频都能找回至少几条有实际意义的缺陷；
- 误报量处于一个人可以快速复核完的水平。

**如果达不到：**先分析是数据问题（画面太糊、角度不对）还是方法问题，再决定要不要调整采集建议或更换领域。

## P6. 需求访谈（与 P2–P5 并行）

### 决策
访谈 15–20 位验房公司老板或验房师，加上少量业主。遵循 *The Mom Test* 的原则：聊对方的经历，不推销自己的想法；问过去发生过的具体事情，不问假设。

### 理由
- 技术上能做到，不等于有人付钱。访谈是成本最低的验证方式。
- 验房公司分散、老板好找，是访谈效率最高的群体。

### 获取信任的阶梯
1. **当客户**：自己请一次验房，全程观察；
2. **请教**："我是做 AI 的工程师，在研究验房怎么做，不卖东西，想请教 20 分钟"；
3. **展示**：给对方看用公开视频跑出来的 demo；
4. **免费帮忙**："给我几段录像和报告，我免费帮你找漏项"；
5. **付费试点**。

### 渠道和理由

| 渠道 | 理由 |
|---|---|
| LinkedIn、公司官网、Google 商家页 | 新加坡商务沟通的主要渠道，能直接联系到老板 |
| 自己付费请一次验房 | 获取第一手流程信息，零门槛的关系起点 |
| Google 差评、HardwareZone 论坛、Reddit、Lemon8 收房帖 | 业主吐槽"漏了什么、损失多少"，是最真实的痛点证据 |
| 政府采购平台 GeBIZ 上的检查类标书 | 甲方要什么、考核什么、怎么罚，全写在里面 |
| 建屋局（HDB）和建设局（BCA）的公开规范 | 了解"什么算缺陷"的官方标准 |

### 必问的问题
1. 带我走一遍你上一次的验房流程。
2. 上一次客户投诉"漏了"是什么情况？后来怎么处理的？花了多少钱或时间？
3. 你们怎么保证新人不漏项？怎么抽查质量？
4. 会录视频吗？录了以后有人看吗？
5. 和开发商或业主起过纠纷吗？那时候缺什么证据？
6. **"多找出缺陷"和"留下可靠证据"，哪个对你的生意更值钱？**
7. （最后才问）愿意给我几段录像试一下吗？还有谁我应该去聊聊？

### 过关标准（进入 P7 的前提）
- 同一个痛点在多次访谈里反复出现；
- **至少 3 家愿意提供录像，或者把你介绍给同行。**

**如果达不到：**回到 P1，换下一个候选领域（优先考虑物业巡检或安保巡逻），P2–P5 的 pipeline 大部分可以复用。

## P7. 免费分析与人工兜底交付

### 决策
用客户提供的真实录像和报告，跑 pipeline，**由创始人复核后**交付漏项报告。

### 理由
- 真实客户的数据比公开视频更能说明问题，而且在真实条件下的召回率才是客户关心的数字。
- 人工兜底能保证早期交付质量，客户买的是结果，不在乎背后是不是全自动。
- 每一次人工复核都转化为评测数据，形成数据飞轮。

### 过关标准（进入 P8 的前提）
- 客户确认报告里有"他们原本漏掉、而且有价值"的条目；
- 客户主动问"这个怎么收费"或者"能不能一直用"。

## P8. 付费试点

### 决策
与 2–3 家验房公司开展小额付费试点。定价方案在访谈中验证后再定，候选：

| 方案 | 适合的情况 |
|---|---|
| 按单次验房收费（附加服务） | 验房公司按单收费，按单定价与他们的成本结构一致，最容易接受 |
| 按验房师人头月费 | 单量大且稳定的公司 |
| 给业主的"AI 复核报告"增值包，由验房公司转售 | 验房公司可以拿它作为差异化卖点，向业主多收费 |

### 理由
- **付费是唯一可靠的信号。**哪怕金额很小，付钱和不付钱是本质区别。
- 定价要贴合客户自身的收费方式，降低他们的决策成本。
- 让验房公司**靠我们多赚钱**（更有竞争力的报告、更高的客单价），比单纯帮他们省钱更好卖。

### 过关标准（进入 P9 和 P10 的前提）
- **至少 2 家付费**，并且试点结束后愿意续费；
- 单次服务的成本远低于收费（模型费用 + 人工复核时间）。

## P9. 证据层 v1

### 决策
为每份报告和每条余光事件附加：原始片段哈希、时间戳、位置（如有）、完整性签名。采用开放的 C2PA 内容溯源标准（使用开源实现，如 c2pa-rs）。

### 理由
- 践行"证"的核心哲学，形成与普通 AI 工具的差异化。
- 验房报告本来就用于索赔和纠纷，**可复核的证据能直接提高索赔成功率**，这对验房公司和业主都是实际利益。
- 它保护的是验房师本人（证明交房时缺陷就存在），有助于一线人员接受。
- 基于开放标准、使用开源实现，成本低，也不锁定在某一家厂商。

### 原则
对外只说"证据链"或"完整性可验证"，不说"证明真相"。

## P10. 产品化

### 决策
在客户付费之后，依次做：
1. 网页上传入口：客户上传视频，自动出报告；
2. 报告导出为客户现有的报告格式（PDF 等）；
3. 人工复核从"每份必审"逐步降低到"抽查"；
4. 接入客户已经在用的检查类 SaaS 工具（如有）。

### 理由
- 在有人付钱之前做界面和产品化，是在为不存在的需求花时间。
- 降低人工复核比例，是从"服务"变成"产品"、从而实现盈利的关键一步。
- 接入客户现有的工具，既降低客户的使用门槛，也为将来被这类平台收购铺路。

---

## P11. 实时化：手机 → 眼镜和边缘设备

### 决策
只有当客户明确提出"现场就要提醒"时才启动，顺序如下：
1. 手机端实时：验房过程中，对清单里还没覆盖到、或者已经出现问题的检查项给出提醒；
2. 接入一个开放的智能眼镜平台；
3. 把门控和轻量识别迁移到端侧低功耗芯片上，只在必要时唤醒摄像头和大模型。

### 理由
- 离线分析已经能交付价值，实时化成本高，必须由需求来驱动。
- 手机是成本最低的实时载体，先在手机上验证提醒是否真的有用、会不会打扰工作。
- 眼镜和端侧芯片解决的是"连续佩戴的电量"和"画面不出设备的隐私"两大问题。这是边缘计算真正发挥价值的地方，也能让余光与各类硬件厂商合作。

---

## P12. 第二个垂直领域或第二个市场

### 决策
在验房领域实现稳定付费之后，从以下方向中选择**能复用最多领域包和 pipeline** 的一个：

| 方向 | 复用度 | 说明 |
|---|---|---|
| 公寓、商业物业交付验收 | 高 | 清单相近，客户更大 |
| 物业和设施巡检 | 中 | 从一次性验房变成周期性巡检，收入更稳定 |
| 安保巡逻 | 中 | 以"证"为主：证明巡逻真实发生、记录异常 |
| 保险理赔查勘 | 中 | 对"证"的需求最强 |
| 中国、澳洲等地的验房市场 | 高 | 同一领域换市场，主要工作是本地化清单 |

### 理由
- 每进入一个新领域都是一次重新验证的成本，复用度越高，风险越低。
- 新加坡市场的上限有限，第二个领域或市场决定了能不能成为一份主业。

---

## P13. 盈利与退出准备

### 盈利路径
- **收入**：多家付费客户加上第二个领域或市场。
- **成本**：控制在模型调用和少量人工复核以内，不养大团队。
- **主业化的信号**：经常性收入稳定覆盖创始人的生活成本，并且新客户主要来自老客户介绍。

### 退出准备（不以此为前提，但要持续积累）
- **潜在收购方类型**：检查和巡检类 SaaS 平台、执法记录仪与证据管理公司、智能眼镜和可穿戴设备厂商、边缘 AI 芯片厂商、内容溯源和保险科技公司。
- **他们看重的资产**：可量化的召回率优势、领域包和评测集、付费客户、证据链能力、干净的知识产权。
- **在他们的平台上构建**：集成越深，越容易被看见、被需要、被收购。
- **公开评测基准**（在不泄露客户数据的前提下）：建立行业影响力和技术可信度。

## 贯穿始终的事项

### 合规
- 遵守新加坡个人数据保护法（PDPA）；与客户签订数据处理约定；支持数据删除和本地部署。
- 公开展示只使用自有或经授权的素材。
- 项目在创始人的个人时间、用个人设备开发，保持知识产权清晰。

### 刻意不做的事（目前）
- 不推断"人看了什么"：余光带着目标去看，不依赖对人注意力的判断；
- 不做自有硬件；
- 不训练基础模型；
- 不做通用平台，不做 C 端；
- 不在付费验证之前做界面、做实时、做多领域。

### 风险登记

| 风险 | 应对 |
|---|---|
| 模型或大厂直接做出同类能力 | 价值放在领域包、评测和证据链上；模型越强，我们越受益 |
| 召回率比不过熟练的验房师 | 定位为人的补充："在你的报告基础上再多找出 N 项" |
| 客户不愿意付费 | P8 过关标准硬卡，不过就换领域；pipeline 可复用 |
| 新加坡市场太小 | 只把它当切入点，P12 尽早规划 |
| "证"被过度解读 | 对外统一口径为证据链，不说证明真相 |
| 一个人精力不够 | 付费验证后，优先找懂行业的合伙人，比如资深验房师 |
